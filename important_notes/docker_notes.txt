docker run ubuntu cat /etc/*release*

    In this command:
    - Container is created from ubuntu image
    - Main process = "cat /etc/*release*"
    - cat reads files and exits
    - As soon as cat exits → container STOPS

    WHY CONTAINER STOPS WITHOUT docker stop
        Because:
        - Container is NOT a virtual machine
        - Container is a wrapper around a process
        - When the main process finishes, container lifecycle ends

When container will stop after running?
- one time task like cat, ls, echo
- build job like npm install 
- script

When container will not stop after running?
- web server like nginx 
- database 
- infinite loop


Application logs hamesha STDOUT / STDERR par likho.

System.out.println()

The best practice for container logging is to write application logs to stdout and stderr, let Docker capture them, and forward them to a centralized logging system with proper rotation and retention.

✔ Logs to STDOUT / STDERR
✔ Use docker logs for debugging
✔ Enable log rotation
✔ Centralize logs
✔ Use JSON + log levels
❌ Don't store logs inside container filesystem

ENTRYPOINT vs CMD – SIMPLE NOTES
================================

ENTRYPOINT:
- Container ka main executable hota hai
- Decide karta hai "kya chalega"
- Usually override nahi karte
- Example:
  ENTRYPOINT ["docker-entrypoint.sh"]

CMD:
- Default command / arguments hoti hain
- Decide karta hai "kaise chalega"
- docker run ke time override ho sakta hai
- Example:
  CMD ["mysqld"]

--------------------------------

ENTRYPOINT + CMD:
- ENTRYPOINT fixed rehta hai
- CMD ENTRYPOINT ke arguments ban jaata hai

Example:
ENTRYPOINT ["echo"]
CMD ["hello"]
Output: hello

--------------------------------

docker run behavior:
- Sirf CMD ho → docker run command CMD ko replace kar deta hai
- ENTRYPOINT + CMD ho → ENTRYPOINT same, CMD replace

CMD override:
- docker run image ls

ENTRYPOINT override:
- docker run --entrypoint /bin/bash image

--------------------------------

Shell vs Exec form:
- Shell form (avoid):
  CMD echo hello
- Exec form (recommended):
  CMD ["echo","hello"]

Reason:
- Exec form me signals properly handle hote hain

--------------------------------

Database images (MySQL example):
- ENTRYPOINT → docker-entrypoint.sh
- CMD → mysqld
- ENTRYPOINT initialization karta hai
- CMD actual service start karta hai

--------------------------------

Extra points:
- ENTRYPOINT ke bina CMD kaam karta hai
- CMD ke bina ENTRYPOINT kaam karta hai
- Multiple CMD allowed nahi (last valid)
- CMD ko argument ki tarah use kar sakte hain

Example:
ENTRYPOINT ["ping"]
CMD ["google.com"]

--------------------------------

When to use:
- ENTRYPOINT → fixed behavior chahiye
- CMD → default + flexible behavior
