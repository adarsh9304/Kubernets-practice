when we create a deployment, it triggers rollout, a new rollout creates a new deployment revision, let's call it revision 1 

we can see the status of our rollout by running the command 
    kubectl rollout status deployment/myapp-deployment 

To see the revision and history of rollout run the command:
    kubectl rollout history deployment/myapp-deployment 

There are two types of deployment strategies 
    one way is to destroy all of these and then create newer versions of application instances, meaning first destroy the five running instances and then deploy five new instances of the new application version, one problem with this strategy is that during the period after the older versions are down and before any new version is up the application is down and inaccessible to users, this strategy is known as recreate strategy 

    in the second strategy we do not destroy all of them at once. instead, we take down the older version and bring up a newer version one by one. this way app never goes down and upgrade is seamless. it is rolling update
    and rolling update is the default deployment strategy

    after rollout if we run the command 
        kubectl get replicas 
        we will have 2 replicaset, one will have zero pods and second will have all pods which indicate one is down and second is up for all instances 


Kubernetes allow us to roll back to a previous revision, to undo a change, run this command
    kubectl rollout undo deployment myapp-deployment

1. POD KYA HAI AUR KIBERNETES ME ISKI ZARURAT KYU PADI?
-----------------------------------------------------------------------------
Direct containers (jaise Docker) use karne ke bajaye Kubernetes "Pod" ka 
concept use karta hai. Pod Kubernetes ka sabse chhota aur basic building block hai.

Direct containers kyu nahi? (Why Pods?):
* Co-scheduling (Saath rehna): Kai applications ko helper containers ki zarurat 
  hoti hai (e.g., Main App + Log Collector/Sidecar). Pod inko ek logical "box" 
  me daal deta hai taaki ye hamesha ek hi machine (Node) par schedule hon.
* Shared Network (Ek IP): Direct containers baat karne ke liye complex networking 
  maangte hain. Pod ke andar saare containers ek hi IP address share karte hain 
  aur aapas me 'localhost' ke zariye baat kar sakte hain.
* Shared Storage: Pod level par hum Storage Volumes define kar sakte hain jise 
  uske andar ke saare containers easily read/write kar sakte hain.
* Abstraction: Kubernetes ko isse farak nahi padta ki piche Docker hai ya Containerd. 
  Wo sirf "Pod" ko manage karta hai. Pod ek universal wrapper hai.

Short Analogy: Container "Sawaari" hai aur Pod "Gaadi" hai. Jahan gaadi jayegi, 
sawaari wahi jayegi.


2. UNDER THE HOOD: ASAL ME POD KYA HOTA HAI?
-----------------------------------------------------------------------------
Linux OS ke andar "Pod" naam ka koi software ya object nahi hota. Pod bas 
ek "Logical Wrapper" (Concept) hai jo Linux namespaces aur cgroups ka use 
karke banaya jata hai.

The Secret Sauce: "Pause Container" (Infra Container)
* Jab aap Pod banate ho, toh Kubernetes sabse pehle ek chhupa hua container 
  chalata hai jise 'Pause' container kehte hain.
* Iska ek hi kaam hai: Ek "Network Namespace" hold karke rakhna.
* Iske baad aapke real application containers (jaise Nginx, Nodejs) start hote 
  hain aur wo naya network banane ke bajaye, is Pause container ke network ko 
  "Join" kar lete hain. Isliye Pod ke saare containers ka IP same hota hai.

Control Groups (cgroups): 
Ye Linux ka feature hai jo memory aur CPU limit karta hai. Kubernetes in cgroups 
ko Pod level par apply karta hai taaki pure group ki limits set ki ja sake.


3. CONFUSION CLEARED: KUBERNETES NAMESPACE vs LINUX NAMESPACE
-----------------------------------------------------------------------------
Dono terms me "Namespace" hai, par dono ka kaam bilkul alag hai:

A. Kubernetes Namespace (Organization tool):
* Ye virtual boundaries hain. Jaise PC me Folders hote hain files rakhne ke liye.
* Example: 'dev' namespace, 'prod' namespace. Iska under-the-hood technical 
  isolation se koi lena-dena nahi hai.

B. Linux Namespace (OS-level Isolation tool):
* Ye Linux Kernel ka jadu hai. Ye process ko feel karata hai ki wo OS me akela hai.
* "Network Namespace": Ye Linux namespace ka ek type hai jo container ko apna 
  private IP, routing table aur ports deta hai. 
* Pod concept isko aise use karta hai: "Ek Pod = Ek Linux Network Namespace".


4. PRACTICAL: PAUSE CONTAINER KO KAISE DEKHEIN?
-----------------------------------------------------------------------------
'kubectl' commands me pause container chhupa hota hai. Ise dekhne ke liye:
1. Pata karo Pod kis worker node par hai: 
   kubectl get pod <pod-name> -o wide
2. Us Worker Node par SSH/Login karo.
3. Wahan container runtime ki command chalao:
   (Agar docker hai): docker ps | grep pause
   (Agar containerd hai): crictl ps | grep pause
Aapko 'registry.k8s.io/pause' image wala ek chhota container dikhega.


5. EXAMPLE: 2 CONTAINERS IN 1 POD (Shared Network YAML)
-----------------------------------------------------------------------------
Niche diye gaye YAML me 2 containers hain. Ek web-server hai, aur dusra curl
karke web-server ko localhost par access kar raha hai.

apiVersion: v1
kind: Pod
metadata:
  name: shared-network-pod
spec:
  containers:
  - name: web-server
    image: nginx
    # Ye port 80 par chalega
  - name: helper-container
    image: radial/busyboxplus:curl
    # Ye 'localhost' par request bhej raha hai jo sidha nginx ke paas jayegi
    command: ['sh', '-c', 'while true; do curl http://localhost; sleep 5; done']

Docker Daemon (Engine): Ye aapke Host OS (Linux) ke Main (Root) Namespace mein hi chalta hai. Ye koi alag duniya mein nahi rehta.

Container creation: Jab aap ek naya container banate ho, toh Docker Linux Kernel ko bolta hai: "Bhai, ek bilkul naya, isolated Network Namespace banao is naye container ke liye."

Multiple Namespaces: Agar aapke paas 5 containers hain, toh system mein 5 alag-alag isolated Network Namespaces banenge. Koi ek "Main Docker Namespace" jaisi chiz nahi hoti jiske andar saare containers hon.

Toh fir Docker Network kaise kaam karta hai?
Agar 5 containers alag-alag namespaces (isolation) mein hain, toh wo aapas me baat nahi kar sakte. Unhe jodne ke liye Docker ye karta hai:

Host OS ke main network mein ek Virtual Switch (Bridge) banata hai (jise docker0 kehte hain).

Har container ke namespace se ek "Virtual Cable" (jise veth pair kehte hain) nikalta hai aur is Bridge (docker0) mein plug kar deta hai.

Is tarah wo isolated hote hue bhi is bridge ke zariye ek dusre se baat kar paate hain.

Part 2: Kubernetes under the hood kya karta hai?
Agar Docker ek akela system manage kar raha hai, toh Kubernetes ek "Orchestrator" (Manager) hai jo bohot saari machines (Nodes) ko ek sath chalata hai.

Kubernetes khud koi container nahi chalata! Wo under the hood sirf Container Runtime (jaise Docker ya Containerd) ko commands deta hai.

K8s dekhta hai ki kis machine par RAM/CPU khali hai.

Agar ek machine fail ho jaye, toh K8s automatically uske containers dusri machine par shift kar deta hai.

K8s multiple machines (nodes) ke beech mein ek Overlay Network (jaise Flannel ya Calico) banata hai, taaki Machine A ka container Machine B ke container se aise baat kare jaise wo ek hi network mein hain.








Ye list aapko hamesha yaad dila degi ki kiske piche kya chal raha hai:

Container = Asal mein Linux ka ek aam Process hai, jisko OS ki baaki duniya se chupa diya gaya hai (Namespace aur Cgroup ka cover pehnakar).

Docker / Containerd = Ye wo Software/Majdoor hai jo Linux OS se baat karke us Process ko isolate karta hai (Namespaces banata hai).

Pod = Ye ek Shared Environment (Ghar) hai. Asal mein ye ek akela Network Namespace hota hai (Pause container banakar), jiske andar ek ya ek se zyada Containers (processes) sath milkar chalte hain.

Kubernetes = Ye ek Manager / Brain hai. Ye khud container nahi banata, bas tay karta hai ki kaunsa Pod kis computer par chalega.
Kubernetes asal me ek Software (Program) hai, jo Go-lang (Go programming language) me likha gaya hai. 

Node = Ye ek Computer / Virtual Machine (Server) hai jisme Linux OS chal raha hai aur RAM/CPU lagi hui hai.

Deployment khud kabhi Pods ko touch nahi karta!
Jab aap image update karte ho (v1 se v2), toh Deployment under the hood ek Naya ReplicaSet (RS-2) banata hai v2 ke liye.

Cluster = Ye ek Group of Computers (Nodes) hai, jo aapas me network se jude hain aur ek single badi machine ki tarah behave karte hain.

ReplicaSet = Ek background while(true) loop jo Desired = Actual match karta hai.

Deployment = Ek aur loop jo naye aur purane ReplicaSets ko scale up/down karta hai.

Service = Linux OS ke kernel me likhe gaye iptables (Routing) rules, aur kuch nahi!
